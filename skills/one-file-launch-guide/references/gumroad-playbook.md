# Gumroad playbook (beginner, digital product)

## One-time account setup (5 min, the user does it)
1. Settings -> Payments: bank or PayPal details (the user types them, never the AI).
2. Settings -> Profile: display name = the brand, upload the logo. Pick the profile URL.

## Make the product (10 min)
Products -> New product -> name -> **Digital product** -> price -> Next.
- Description: first line = the promise; then "what is inside", "who it is for", "what it is NOT", licence + refund line. No income promises.
- Cover: 1280x720 JPG (cover 1 = the hero image), up to 4 covers; thumbnail 600x600.
- Content tab: upload the ONE buyer file (an .html or .pdf). One file = fewer support emails.
- Summary line (one sentence) for the card.

## Launch (5 min)
- Refund policy: 30 days (raises trust, few people use it).
- Product URL ending: short and readable (`life-story-website`).
- Discount code `LAUNCH`: 35% off, limit 20 uses, ends in 7 days.
- Publish; copy the link; paste into the guide's top bar and press Sync.

## Pricing logic
- Guides/blueprints that save someone a week of work: list $29, launch price about $19 via code (scarcity: first 20 buyers, 7 days). After ~10 sales end the code. Raise the list price later if people buy without discount.
- Fees: Gumroad takes about 10% + $0.50 per sale plus card processing (third-party figures; check the current Gumroad pricing page). Payout minimums and schedule vary: check Settings -> Payments.
- Do not underprice below $9: it signals low value and refunds cost the same effort.

## Wording the product
- Promise + proof (a real build, real numbers) beats features.
- "What it is not" builds trust ("Not a one-click generator, not a template").
- Byline pattern: "By <First name> x <Brand>". No other personal details.
